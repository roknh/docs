1. Tổng quan

1.1. Mục đích

Catcuri là nền tảng Learning Management System (LMS) dạng SaaS dành cho doanh nghiệp. Mỗi tổ chức (tenant/công ty) đăng ký sử dụng nền tảng và tự chủ toàn bộ nội dung đào tạo: tạo bài giảng, bài kiểm tra, câu hỏi, topic, khoá học, kỳ thi riêng — chỉ dành cho nhân viên của mình. Dữ liệu giữa các tenant hoàn toàn độc lập.

Super Admin (quản trị nền tảng) có thể tạo nội dung ở cấp hệ thống và chia sẻ cho một hoặc nhiều tenant — ví dụ: khoá học miễn phí, nội dung đào tạo chuẩn ngành. Tenant nhận nội dung được chia sẻ dưới dạng read-only, có thể clone về để tuỳ chỉnh thành bản riêng.

Hệ thống dùng 1 giao diện Admin Dashboard chung — menu hiển thị theo role và quyền hạn. Người dùng đăng nhập bằng email/mật khẩu, chọn tenant context để truy cập.

1.3. Mục tiêu kinh doanh

  • Cung cấp nền tảng SaaS đào tạo trực tuyến cho nhiều doanh nghiệp
  • Mỗi doanh nghiệp (tenant) tự chủ toàn bộ nội dung và chương trình đào tạo
  • Super admin cung cấp nội dung chuẩn / khoá học miễn phí dùng chung cho các tenant
  • Quản lý năng lực nhân sự thông qua bài kiểm tra và kỳ thi
  • Cấp chứng chỉ hoàn thành khoá học tự động
  • Theo dõi tiến độ học tập

In-scope:

  • CASL conditions tự động thêm tenant_id = currentTenantId cho tenant admin → đảm bảo data isolation

2.3. Chi tiết từng tính năng

F1 — Đăng nhập / Đổi mật khẩu

User story:

Là một người dùng, tôi muốn đăng nhập bằng email và mật khẩu, để truy cập hệ thống đào tạo.

Luồng xử lý:

  1. User nhập email + password
  2. Tìm user theo email
  3. Không tìm thấy → trả lỗi USER_NOT_FOUND
  4. Xác thực password → so sánh
  5. Kiểm tra status = ACTIVE, deleted_at = null
  6. Tạo session/token, trả về: token, role_name, rules, user info
  7. Sau khi đăng nhập, user thấy danh sách tenant mà mình thuộc về (xem F12)

Acceptance criteria:

  • Login bằng email + password, trả token
  • Password sai → báo lỗi INVALID_PASSWORD
  • User không tồn tại → báo lỗi USER_NOT_FOUND
  • User INACTIVE → báo lỗi INACTIVE_USER
  • Lần đăng nhập đầu tiên (is_changed_password = false) → bắt buộc đổi mật khẩu
  • Đổi mật khẩu: nhập mật khẩu cũ + mới, password mới ≠ cũ
  • Quên mật khẩu: nhập email → nhận OTP → đặt mật khẩu mới
  • Admin có thể reset password user
  • Logout: huỷ session/token

F2 — Đăng ký tài khoản (OTP email)

User story:

Là một người dùng mới, tôi muốn đăng ký bằng email với xác thực OTP, để tạo tài khoản học tập.

Luồng:

  1. Nhập email → gửi OTP (6 chữ số, TTL 5 phút) qua email
  2. Nhập OTP xác thực
  3. Hoàn tất đăng ký: email + password → tạo user với role user
  4. Auto login, trả JWT token

Acceptance criteria:

  • Email trùng → báo lỗi DATA_EXIST
  • OTP hết hạn → báo lỗi OTP_EXPIRED
  • OTP sai → báo lỗi OTP_CODE_NOT_EXACTLY
  • Hỗ trợ resend OTP

F3 — Quản lý khoá học

User story:

Là một admin/tenant admin, tôi muốn tạo khoá học, gán bài giảng và chỉ định học viên, để tổ chức đào tạo có thời hạn và theo dõi tiến độ.

Khái niệm: Khoá học là đơn vị tổ chức đào tạo — không chứa nội dung trực tiếp. Nội dung lấy từ Thư viện Bài giảng (F4). Khoá học quản lý: ai học, học khi nào, tiến độ ra sao.

Khoá học = Bài giảng (từ thư viện) + Học viên + Thời gian + Tiến độ

Tenant scoping (F25):

  • tenant_id = null → khoá học hệ thống (admin tạo, có thể chia sẻ cho nhiều tenant)
  • tenant_id = X → khoá học riêng của tenant X (tenant admin tạo, chỉ nhân viên tenant X thấy)
  • Tenant admin tạo khoá học → tenant_id tự động gán theo tenant hiện tại
  • Tenant admin chỉ chọn được bài giảng thuộc tenant mình hoặc được admin chia sẻ

Thông tin khoá học:

Trường Kiểu Bắt buộc Mô tả
name String Có Tên khoá học
description String Không Mô tả chi tiết
avatar String Không Ảnh đại diện (upload)
type Enum Có COURSE (khoá học) / COMPETENCY (từ điển năng lực)
curriculum ObjectId Có Bài giảng từ thư viện (1 khoá = 1 bài giảng)
topic ObjectId Có Thuộc bộ kỹ năng nào
tenant_id ObjectId Không null = hệ thống, có giá trị = tenant cụ thể
start_date Date Có Ngày bắt đầu khoá học
end_date Date Có Ngày kết thúc khoá học
is_certification Boolean Không Có cấp chứng chỉ không
template String Không Template chứng chỉ

Gán học viên:

  • Admin (khoá hệ thống): gán trực tiếp user hoặc theo bộ lọc tenant + phòng ban + chức danh (cross-tenant)
  • Tenant admin (khoá tenant): gán nhân viên trong tenant mình, lọc theo phòng ban + chức danh
  • Khi gán → hệ thống gửi thông báo cho học viên rằng khoá học đã được kích hoạt
  • Học viên chỉ thấy khoá học mình được gán (không tự đăng ký)

Trạng thái khoá học:

  • DRAFT (mặc định khi tạo) → chưa có học viên
  • ACTIVE → đã publish, học viên được gán có thể học
  • INACTIVE → tạm dừng, học viên không truy cập được
  • COMPLETED → đã hết hạn end_date

Acceptance criteria:

  • CRUD khoá học (tạo, xem, sửa, xoá)
  • Chọn 1 bài giảng từ thư viện khi tạo/sửa khoá
  • Bắt buộc nhập start_date và end_date
  • Gán học viên: chọn user cụ thể hoặc theo bộ lọc (tenant/phòng ban/chức danh)
  • Gửi thông báo cho học viên khi được gán vào khoá
  • Publish / Unpublish khoá học
  • Xem danh sách học viên + tiến độ + điểm kiểm tra
  • Export kết quả học viên ra Excel
  • Upload ảnh đại diện
  • Tự động tính total_resources và total_videos_time từ bài giảng

F4 — Thư viện Bài giảng (Curriculum Library)

User story:

Là một admin/tenant admin, tôi muốn tạo bài giảng trong thư viện nội dung, để tái sử dụng cho nhiều khoá học khác nhau.

Khái niệm: Bài giảng là gói nội dung học tập độc lập, được quản lý trong thư viện. Một bài giảng có thể được gán cho nhiều khoá học. Khi sửa bài giảng, tất cả khoá học đang dùng đều cập nhật ngay (live update).

Tenant scoping (F25):

  • tenant_id = null → bài giảng hệ thống (admin tạo)
  • tenant_id = X → bài giảng riêng của tenant X
  • Tenant admin chỉ thấy: bài giảng của tenant mình + bài giảng được admin chia sẻ (read-only, có thể clone)
  • Admin thấy tất cả bài giảng hệ thống + có thể xem bài giảng của từng tenant

Cấu trúc:

Thư viện Bài giảng (trong context tenant X)
├── [Tenant] Bài giảng "Kỹ năng giao tiếp"      ← tenant X tự tạo
│   ├── Chương 1: Giao tiếp cơ bản
│   │   ├── Bài 1.1: Video giới thiệu (Video)
│   │   └── → Bài kiểm tra (từ Thư viện Test tenant X)
│   └── ...
├── [Shared] Bài giảng "An toàn lao động"         ← admin chia sẻ (read-only)
│   └── ... (không sửa được, có thể clone)
├── [Cloned] Bài giảng "An toàn lao động (tuỳ chỉnh)" ← clone từ shared
│   └── ... (sửa thoải mái)

F5 — Học khoá học

User story:

Là một người học, tôi muốn xem video bài giảng, đọc tài liệu và ghi chú, để hoàn thành khoá học.

Luồng truy cập:

  • Học viên được admin gán vào khoá → nhận thông báo → truy cập khoá học
  • Nội dung bài giảng lấy từ Thư viện Bài giảng (F4) đã gán cho khoá
  • Bài kiểm tra lấy từ Thư viện Bài kiểm tra (F6) đã gán trong bài giảng

Màn hình học:

  • Sidebar trái: danh sách chương → bài học + bài kiểm tra với icon trạng thái
  • Nội dung chính: video player hoặc PDF viewer hoặc nội dung HTML
  • Tab ghi chú: tạo/sửa/xoá ghi chú cá nhân cho từng bài học
  • Tài liệu đính kèm: download dropdown

Tiến độ học tập:

  • Mỗi resource theo dõi is_completed, completed_at
  • progress_rate = số resource hoàn thành / tổng resources × 100%
  • Hoàn thành tất cả → hiển thị màn hình CourseFinal
  • Nếu khoá học có chứng chỉ → tự động gửi email với PDF chứng chỉ

Acceptance criteria:

  • Chỉ học viên được gán mới truy cập được khoá học
  • Chỉ truy cập được trong khoảng start_date → end_date
  • Xem video với player hỗ trợ seek, pause, fullscreen
  • Xem tài liệu PDF inline
  • Ghi chú: CRUD per lesson per user
  • Tải tài liệu đính kèm
  • Đánh dấu bài học hoàn thành (auto hoặc manual tuỳ config)
  • Theo dõi progress_rate realtime
  • Tự động navigate đến resource đang dở
  • Hoàn thành khoá → hiển thị màn hình chúc mừng
  • Gửi chứng chỉ qua email khi hoàn thành (nếu có template)

F6 — Thư viện Bài kiểm tra (Test Library)

User story:

Là một admin/tenant admin, tôi muốn tạo bài kiểm tra trong thư viện, để tái sử dụng trong nhiều bài giảng và kỳ thi.

Khái niệm: Bài kiểm tra là entity độc lập, quản lý trong thư viện. Có thể được gán vào chương của bài giảng (F4) hoặc vào kỳ thi (F7). Khi sửa bài kiểm tra → tất cả nơi đang dùng cập nhật tức thì.

Tenant scoping (F25): Tương tự F4 — tenant_id nullable, tenant admin chỉ thấy data của tenant mình + shared (read-only, cloneable).

Thông tin Bài kiểm tra:

Trường Kiểu Mô tả
name String Tên bài kiểm tra
description String Mô tả
topic ObjectId Phân loại theo bộ kỹ năng (Topic)
tags [String] Tags tự do để phân loại, tìm kiếm
tenant_id ObjectId null = hệ thống, có giá trị = tenant cụ thể
test_time Number Thời gian làm bài (phút)
completion_rate Number Ngưỡng đạt (%) — mặc định 100%
num_of_retake Number Số lần làm lại
num_of_random_question Number Số câu hỏi ngẫu nhiên (lấy từ pool)
questions [ObjectId] Danh sách câu hỏi (từ ngân hàng F8)
status Enum DRAFT / PUBLISHED
cloned_from ObjectId ID gốc nếu được clone

Luồng làm bài (phía học viên):

  1. Click vào test trong sidebar bài giảng → hiển thị thông tin: thời gian, số câu, ngưỡng đạt
  2. Bấm "Bắt đầu" → hệ thống tạo UserTest, random câu hỏi (nếu có config), bắt đầu đếm ngược
  3. Trả lời từng câu (MC: radio, MR: checkbox)
  4. Submit → tính điểm theo rule hoàn thành
  5. Hiển thị kết quả: đạt/không đạt, số câu đúng, tỷ lệ
  6. Nếu không đạt và còn lượt → cho phép "Làm lại"

Rule hoàn thành (mặc định):

  • Mặc định completion_rate = 100% (đúng hết mới đạt)
  • Có thể cấu hình theo từng bài kiểm tra (VD: 80% = đạt)

Acceptance criteria:

  • CRUD bài kiểm tra trong thư viện
  • Phân loại theo topic + gắn tags
  • Tìm kiếm / lọc theo tên, topic, tags
  • Gán câu hỏi từ ngân hàng câu hỏi (F8)
  • Import câu hỏi từ Excel
  • Cấu hình: thời gian, ngưỡng đạt, số lần làm lại, random câu hỏi
  • Publish / Unpublish bài kiểm tra
  • Hiển thị danh sách bài giảng / kỳ thi đang sử dụng
  • Sửa bài kiểm tra → cập nhật tức thì (live update)
  • Cảnh báo trước khi xoá nếu đang được sử dụng
  • Đếm ngược thời gian (tự động submit khi hết giờ)
  • Hỗ trợ câu hỏi MC (chọn 1) và MR (chọn nhiều)
  • Giới hạn số lần làm lại (num_of_retake)
  • Lưu kết quả cao nhất (highest_user_test)
  • Resume bài kiểm tra đang dở (nếu chưa submit)

F8 — Quản lý câu hỏi

User story:

Là một admin/tenant admin, tôi muốn quản lý ngân hàng câu hỏi, để tái sử dụng trong nhiều bài kiểm tra.

Tenant scoping (F25): Mỗi tenant có ngân hàng câu hỏi riêng biệt (tenant_id). Tenant admin không thấy câu hỏi của tenant khác. Câu hỏi hệ thống (tenant_id = null) có thể được chia sẻ và clone.

Loại câu hỏi:

Type Mô tả Trạng thái
MC Trắc nghiệm chọn 1 đáp án Đang dùng
MR Trắc nghiệm chọn nhiều đáp án Đang dùng
FIB Điền vào chỗ trống Model có, UI chưa
MD Nối/kéo thả Model có, UI chưa
SA Trả lời ngắn Model có, UI chưa

Cấu trúc câu hỏi:

  • content: nội dung câu hỏi
  • answers: mảng { label, value } — các đáp án
  • correct_answers: mảng label của đáp án đúng
  • topic: phân loại theo bộ kỹ năng (Topic)
  • tags: tags tự do để phân loại, tìm kiếm
  • difficulty_level: độ khó — EASY / MEDIUM / HARD (dùng cho AI adaptive testing F23)

Acceptance criteria:

  • CRUD câu hỏi
  • Phân loại theo topic + gắn tags
  • Tìm kiếm / lọc theo tên, topic, tags
  • Import câu hỏi từ Excel (sheet QUESTIONS, đánh dấu đáp án đúng bằng ***)
  • Upload hình ảnh cho câu hỏi
  • Xoá hàng loạt (bulk delete)

F9 — Quản lý bộ kỹ năng / Topic + Tags

User story:

Là một admin/tenant admin, tôi muốn tổ chức nội dung theo bộ kỹ năng (topic) và tags, để phân loại và tìm kiếm bài giảng, bài kiểm tra, câu hỏi dễ dàng.

Topic — phân loại chính, cấu trúc cây:

  • Dùng cho: Bài giảng, Bài kiểm tra, Câu hỏi, Khoá học, Kỳ thi
  • Mỗi entity thuộc 1 topic (bắt buộc)
  • VD: Kỹ năng mềm > Giao tiếp, An toàn > PCCC

Tenant scoping (F25): Mỗi tenant có cây topic hoàn toàn độc lập (tenant_id). Admin có cây topic riêng ở cấp hệ thống (tenant_id = null). Khi chia sẻ nội dung, topic gốc đi kèm nhưng tenant có thể gán lại topic của mình khi clone.

Tags — phân loại phụ, tự do:

  • Dùng cho: Bài giảng, Bài kiểm tra, Câu hỏi
  • Mỗi entity có thể gắn nhiều tags (không bắt buộc)
  • Mỗi tenant quản lý tags riêng (tenant_id), ngoài tags hệ thống
  • Tags do admin/tenant admin tạo tự do, gợi ý autocomplete từ tags đã có trong scope
  • VD: "onboarding", "bắt buộc", "Q2-2026", "phòng-kỹ-thuật"

Acceptance criteria:

  • CRUD topic (tên, mô tả, hình ảnh)
  • Topic có cấu trúc cây (parent/child)
  • Drag-and-drop sắp xếp thứ tự
  • Topic type: COURSE / COMPETENCY / EXAM
  • Import/Export Excel
  • Quản lý tags: tạo, sửa, xoá, merge tags trùng
  • Autocomplete tags khi gắn (gợi ý từ tags đã có trong scope tenant)
  • Xem danh sách nội dung theo tag
  • Mỗi tenant có cây topic và tags hoàn toàn độc lập

F11 — Quản lý Tenant

User story:

Là một admin, tôi muốn quản lý các tenant (tổ chức) trên nền tảng, để mỗi tổ chức có không gian đào tạo riêng biệt.

Vòng đời tenant:

Đăng ký (PENDING) → Admin duyệt (ACTIVE) → Hoạt động
                   → Admin từ chối (REJECT)
ACTIVE → Admin vô hiệu (INACTIVE) → tất cả user tenant bị hạ role về "user"

Khi duyệt tenant:

  • Tự động tạo user super-moderator cho tenant
  • Gửi email thông báo
  • Tenant admin truy cập Admin Dashboard → tự động filter theo tenant context

Quản lý nhân sự tenant (trong Admin Dashboard): Tenant admin (super-mod/moderator) quản lý trong cùng giao diện Dashboard, nhóm menu "Quản lý":

  • Quản lý nhân viên (CRUD, import/export, mời qua email)
  • Quản lý phòng ban (cây phân cấp, drag-drop)
  • Quản lý chức danh (cây phân cấp, drag-drop)

Quản lý nội dung & đào tạo tenant: Tenant admin sử dụng cùng giao diện Dashboard để tạo nội dung riêng:

  • Thư viện: Bài giảng, Bài kiểm tra, Câu hỏi, Topics (tất cả scoped theo tenant)
  • Đào tạo: Khoá học, Kỳ thi (gán nhân viên trong tenant)
  • AI: Course Builder (nội dung tạo thuộc tenant)
  • Nội dung admin chia sẻ hiển thị dạng read-only, có thể clone

Acceptance criteria:

  • Đăng ký tenant (form public, không cần login)
  • Admin: duyệt / từ chối / kích hoạt / vô hiệu tenant
  • Auto tạo super-moderator khi duyệt
  • Tenant admin dùng Admin Dashboard với menu/data filter theo tenant
  • CRUD phòng ban, chức danh, nhân viên trong Dashboard
  • Import/Export Excel cho phòng ban, chức danh, nhân viên
  • Tenant admin tự tạo/quản lý toàn bộ nội dung trong tenant
  • Mời nhân viên qua email (invitation link)

14.1. Khoá học của tôi (S11):

Danh sách tất cả khoá học mà học viên đã được gán, phân loại theo trạng thái:

Trạng thái Điều kiện Hiển thị
Chưa bắt đầu progress_rate = 0%, trong thời hạn Badge neutral, nút "Bắt đầu"
Đang học 0% < progress_rate < 100%, trong thời hạn Progress bar %, nút "Tiếp tục"

Hết hạn Chưa hoàn thành + end_date < now Badge error, progress bar (frozen)

  • S11: Khoá sắp hết hạn (≤ 7 ngày) hiện badge cảnh báo

F15 — Quản lý tiến độ học viên (quản lý)

F19 — 🤖 AI — Sinh câu hỏi & tóm tắt nội dung

19.1. Sinh câu hỏi từ nội dung bài giảng (F8 + F4):

Admin chọn bài học (video/doc/HTML) hoặc cả bài giảng
  → Nhấn "AI sinh câu hỏi"
  → Cấu hình: số lượng, độ khó (dễ/trung bình/khó), loại (MC/MR)
  → AI phân tích nội dung → sinh câu hỏi + đáp án + đáp án đúng
  → Admin review từng câu: chấp nhận / sửa / bỏ
  → Lưu vào ngân hàng câu hỏi (F8), tự gắn topic + tags từ bài giảng nguồn

Yêu cầu chất lượng câu hỏi AI:

  • Câu hỏi phải bám sát nội dung bài học, không bịa thông tin ngoài
  • Đáp án nhiễu (distractor) phải hợp lý — sai nhưng có vẻ đúng, tránh đáp án vô nghĩa
  • Không sinh câu hỏi trùng hoặc quá giống nhau
  • Mỗi câu phải có đúng 1 đáp án đúng (MC) hoặc ≥2 đáp án đúng (MR)

19.2. Tạo transcript từ video (F4):

Admin upload video bài giảng
  → AI tự động tạo transcript (speech-to-text)
  → Transcript có thể dùng làm nội dung bài học dạng text
  → Là nguồn dữ liệu để AI sinh câu hỏi, tóm tắt

19.3. Tóm tắt nội dung bài giảng (F4):

Admin chọn bài giảng có nhiều chương / bài
  → Nhấn "AI tóm tắt"
  → AI sinh:
    - Mô tả tổng quan bài giảng (dùng làm description)
    - Key points cho từng chương
    - Gợi ý chia chương (nếu tài liệu chưa chia)
  → Admin review + chỉnh sửa → lưu

Acceptance criteria:

  • Nút "AI sinh câu hỏi" trong màn chi tiết bài giảng (S54) và ngân hàng câu hỏi (S45)
  • Cấu hình: chọn nguồn nội dung, số lượng câu, độ khó, loại câu hỏi
  • AI sinh câu hỏi + 4 đáp án + đánh dấu đáp án đúng
  • Giao diện review: xem từng câu, sửa inline, chấp nhận / bỏ / sinh lại
  • Tự động gắn topic + tags từ bài giảng nguồn
  • Tự động tạo transcript khi upload video
  • Nút "AI tóm tắt" cho bài giảng → sinh mô tả + key points
  • AI chỉ sử dụng nội dung bài học làm nguồn, không bịa thêm

F20 — 🤖 AI — Trợ lý học tập (AI Tutor)

User story:

Là một người học, tôi muốn hỏi AI về nội dung bài đang học, để hiểu sâu hơn mà không cần chờ giảng viên trả lời.

Mô tả: Chatbot AI tích hợp trong màn hình học (S13), trả lời câu hỏi của học viên dựa trên nội dung bài giảng hiện tại. AI được giới hạn chỉ trả lời trong phạm vi nội dung khoá học (grounded), không bịa thông tin ngoài.

Flow:

Học viên đang xem bài "Kỹ thuật thuyết trình"
  → Nhấn icon chat (góc phải dưới)
  → Mở panel chat
  → Hỏi: "3 nguyên tắc quan trọng nhất là gì?"
  → AI trả lời dựa trên nội dung bài học
  → Có thể gợi ý: "Xem thêm ở Chương 2, Bài 2.1"
  → Lịch sử chat lưu theo khoá học + user

Phạm vi trả lời:

  • AI chỉ trả lời dựa trên nội dung bài giảng đã gán cho khoá học
  • Nếu câu hỏi ngoài phạm vi → trả lời: "Câu hỏi này nằm ngoài nội dung khoá học"
  • Có thể tham chiếu đến bài học / chương cụ thể trong bài giảng

Acceptance criteria:

  • Chat panel trong màn hình học (S13) — thu gọn / mở rộng
  • AI trả lời dựa trên nội dung bài giảng hiện tại (grounded)
  • Từ chối trả lời câu hỏi ngoài phạm vi nội dung
  • Gợi ý tham chiếu đến bài học / chương liên quan
  • Lưu lịch sử chat per user per khoá học
  • Admin có thể bật/tắt AI Tutor cho từng bài giảng
  • Giới hạn số lượt hỏi / ngày (cấu hình được) để kiểm soát chi phí

F21 — 🤖 AI — Auto-tagging & tìm kiếm ngữ nghĩa

  • Thanh tìm kiếm hỗ trợ semantic search (tìm theo ý nghĩa)

F23 — 🤖 AI — Kiểm tra thích ứng & phân tích chất lượng

23.1. Phân tích chất lượng câu hỏi (F8 + F6):

Sau khi có đủ dữ liệu làm bài (>50 lượt), AI phân tích:

  • Câu hỏi quá dễ (>95% đúng) → gợi ý tăng độ khó hoặc loại bỏ
  • Câu hỏi quá khó (<10% đúng) → gợi ý xem lại đề hoặc đáp án
  • Đáp án nhiễu không hiệu quả (không ai chọn) → gợi ý thay thế
  • Câu hỏi có tỷ lệ bỏ qua cao → có thể đề bài không rõ ràng

23.2. Kiểm tra thích ứng — Adaptive Testing (F6):

Thay vì random câu hỏi, AI chọn câu theo trình độ:

Câu 1: trung bình → đúng
Câu 2: khó → sai
Câu 3: trung bình → đúng
Câu 4: trung bình-khó → ...
  • Đánh giá chính xác hơn với ít câu hỏi hơn
  • Yêu cầu: mỗi câu hỏi phải có metadata difficulty_level
  • Admin chọn chế độ: Random (mặc định) hoặc Adaptive

23.3. Phát hiện bất thường (F6/F7):

  • Thời gian trả lời bất thường nhanh (< 3 giây / câu)
  • Nhiều học viên có câu trả lời giống nhau theo cùng pattern
  • Đánh dấu kết quả nghi ngờ → admin review

Acceptance criteria:

  • Báo cáo chất lượng câu hỏi trong màn ngân hàng câu hỏi (S45)
  • Gợi ý cải thiện câu hỏi kém chất lượng
  • Chế độ Adaptive Testing (bật/tắt per bài kiểm tra)
  • Thêm difficulty_level cho câu hỏi (dễ / trung bình / khó)
  • Phát hiện và đánh dấu kết quả bất thường
  • Admin review danh sách kết quả nghi ngờ

User story:

    - Curriculum → copy chapters, lessons, gán test
    - Test → copy, gán câu hỏi (reference hoặc clone)

  → Tenant admin có toàn quyền sửa bản sao

  • Clone tất cả chapters → gán vào curriculum mới

  • Tests trong chapters: giữ reference nếu test cũng được shared, hoặc clone test
  • Topic: gán về topic của tenant (cần tenant admin chọn lại topic)

  • Tab/Filter "Của tôi": nội dung tenant tự tạo + bản clone

  • Nội dung tenant = read-only từ góc nhìn admin (không sửa/xoá)
  • Mục đích: giám sát chất lượng, hỗ trợ tenant

  • Admin login: sidebar đầy đủ (Thư viện + Đào tạo + AI + Quản lý Tenant/Users + Báo cáo + Hệ thống)
  • Tenant admin login: sidebar chỉ hiện menu được phép (Thư viện + Đào tạo + AI + Quản lý nhân sự + Báo cáo)
  • Header hiển thị tenant context: [Tên Tenant] — giúp phân biệt đang làm việc ở scope nào
  • Admin có thêm dropdown "Xem tenant" để xem nội dung của tenant cụ thể

Acceptance criteria:

  • Tất cả entity nội dung có tenant_id (nullable) để phân tách dữ liệu
  • Tenant admin CRUD toàn bộ nội dung trong scope tenant mình
  • Data isolation: tenant A không thấy/truy cập data tenant B
  • Admin tạo nội dung hệ thống (tenant_id = null)
  • Admin chia sẻ nội dung cho 1 hoặc nhiều tenant (hoặc tất cả)
  • Nội dung shared hiển thị read-only ở phía tenant, đánh dấu [Shared]
  • Clone nội dung shared → tạo bản sao thuộc tenant, có toàn quyền sửa
  • Deep clone Curriculum: copy curriculum + chapters + lessons + tests + questions
  • Clone giữ cloned_from để traceability
  • Admin Dashboard: menu sidebar filter theo role (admin vs tenant admin)
  • Header hiển thị tenant context
  • Admin có thể xem (read-only) nội dung của từng tenant
  • CASL conditions auto-inject tenant_id cho tenant admin

  • Tính XP khi hoàn thành lesson, chapter, course, test, exam, streak, badge
  • Mỗi action chỉ tính XP 1 lần (idempotent)
  • Level tự động tăng khi đủ XP, thông báo + animation
  • Leaderboard tuần/tháng/tổng, scope per tenant
  • Leaderboard filter theo phòng ban
  • Tenant admin bật/tắt toàn bộ gamification
  • Tenant admin tuỳ chỉnh XP rules và level table
  • XP transaction log (audit trail)
  • Hiển thị XP bar + level trên profile và trang chủ
  • Toast "+X XP" sau mỗi hành động tính điểm
  • Gamification tắt mặc định — tenant tự bật khi muốn

3. Yêu cầu phi chức năng

3.1. Performance

  • Response time API: < 500ms cho 95% request
  • Rate limit: 1500 requests / 5 phút / IP
  • Request body limit: 50MB
  • Pagination mặc định: 10 items/page, tối đa 100

3.2. Security

  • Auth: token-based (JWT hoặc tương đương)
  • Password: hash an toàn (bcrypt, argon2, hoặc tương đương)
  • CORS: chỉ cho phép domain hợp lệ
  • Soft delete: không xoá vĩnh viễn dữ liệu
  • Attribute-based access control per role (CASL hoặc tương đương)

3.3. Compatibility

  • Web: responsive, SPA
  • Browser: Chrome, Safari, Firefox (modern versions)
  • Mobile: deep link support (chưa có app trong scope)

3.4. Availability

  • Logging: structured logging với daily rotation
  • Alert: gửi thông báo lỗi qua kênh chat (optional)

3.5. Ngôn ngữ

  • Giao diện: Tiếng Việt (primary), English (partial)
  • i18n: hỗ trợ đa ngôn ngữ với locale files

8. Multi-tenant & Data Isolation

Catcuri là nền tảng SaaS — nhiều tổ chức (tenant/công ty) dùng chung 1 instance (shared database, shared codebase), nhưng dữ liệu hoàn toàn độc lập giữa các tenant.

Quy tắc data isolation:

  • 1 user đăng nhập bằng email/password → thấy danh sách tenant mình thuộc về → chọn tenant context
  • Tenant admin chỉ thấy data có tenant_id = currentTenantId + shared content
  • Tenant A không thể thấy hoặc truy cập data của Tenant B (enforced ở API layer)
  • Admin hệ thống thấy data tất cả tenant (read-only) + data hệ thống (full CRUD)
  • Mỗi tenant có thể có branding riêng (logo, primary color) — cấu hình trong DB

Chia sẻ nội dung (chi tiết xem F25):

  • Chỉ Admin mới có quyền chia sẻ nội dung cross-tenant
  • Nội dung shared = read-only ở phía tenant, có thể clone để tạo bản sao riêng
  • Entity SharedContent quản lý mapping: content_id → tenant_id
